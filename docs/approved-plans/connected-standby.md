# 已核准方案：連線省電待機與區網管理

- 核准日期：2026-09-17。
- 狀態：**設計已核准；韌體實作與實機驗收尚未完成。**
- 檢查基準：`03d6f795cd770e88be90ec662844c9536920363f`。
- 本文件不是目前已支援功能的說明。這份文件的加入不會改變韌體、預設模式、管理介面、偵測規則或裝置設定。

## 1. 目標與已定案界線

在不開啟 ESP32 熱點的前提下，提供獨立、可切換的「連線省電待機」模式。使用者從家中區網開啟裝置網址，即可進入受保護的管理介面；沒有工作時，系統利用 Wi-Fi Modem-sleep 與自動 Light-sleep 省電。

這不是讓已經 `WIFI_OFF` 的裝置收到 HTTP 請求，而是保留 STA 關聯、IP 網路與 HTTPS 監聽，由系統協調省電與收訊。

以下事項不再作為未決需求：

1. 保留離線低功耗模式，並維持為正式預設；連線省電待機先作為可選模式，不因本方案核准就改成預設。
2. 只使用 STA，不啟動 AP 或 AP+STA；連線失敗、密碼未設定或錯誤、運行中斷線、除錯模式都不得回退到開放熱點。隱藏 SSID 不是替代方案。
3. 連線待機不得重用 `DEBUG_WEB_SERVER` 當開關。除錯設定不得繞過管理驗證、TLS、安全失敗處理或獨立模式選擇。
4. 安全管理入口必須先完成，再啟用長時間可達的連線待機；不能先把目前未驗證的 HTTP OTA 改為永久在線。
5. 不更改已實測的入口門檻、待機／事件取樣週期、RFID 逾時或離開判定語意。相關參數仍以 `firmware/main/app_config.h` 為唯一來源。
6. 不承諾續航不受影響，不承諾只有正確密碼的封包才會喚醒處理器。不得以硬體支援、API 呼叫成功或主機端測試通過代替實機省電證據。

## 2. 模式與對外行為

| 項目 | 離線低功耗 | 連線省電待機 |
|---|---|---|
| 一般待機網路 | Wi-Fi 關閉 | 保持家中 Wi-Fi STA 連線 |
| 管理入口 | 僅維護窗口提供 | 安全入口持續監聽 |
| 隨時開啟網址 | 不支援，窗口外裝置不可達 | 支援，但連線延遲需要實测 |
| 省電機制 | 離線取樣間的手動 Light-sleep | 系統協調 Modem-sleep／自動 Light-sleep |
| 管理操作結束 | 回到離線低功耗 | 回到連線省電待機，不關閉必要的監聽入口 |
| 正式預設 | 是 | 否，待驗收後另行決定 |

模式選擇須有明確、獨立的設定，不要求新增完整設定平台或帳戶系統。首版至少提供可重現的編譯期模式選擇；是否提供執行期切換另行處理，不能用暗中修改除錯開關代替。

區分「設定的模式」與「實際生效的模式」。若因缺少安全設定或省電能力而拒絕進入連線待機，必須記錄明確原因，不能顯示已經處於連線省電待機。

`/normal` 與按鈕文案須反映選定模式：結束管理活躍狀態不一定等於 Wi-Fi 關閉。不得在連線待機中沿用會停止全部監聽的舊收尾路徑。

`192.168.1.3` 是預期的 ESP32 區網位址，不是 ESP32 要連線的路由器位址。建議由路由器對 STA MAC 做 DHCP 位址保留；不在未確認子網路、閘道及 DNS 的情況下寫死完整靜態網路設定。

## 3. 安全前置條件

本節承接已討論的 STA-only 與安全 OTA 方向；不是宣稱這些功能已存在。

### 3.1 HTTPS 與管理驗證

- 使用單一管理帳密，不共用家中 Wi-Fi 密碼或 Apps Script `DEVICE_TOKEN`。
- 密碼、TLS 私鑰及其他機密只留在本機私密設定，不提交公開 repository，不輸出到診斷、頁面或 log。
- 未設定有效管理憑證時，管理服務不開放；偵測與離線紀錄仍應運作。不得降級成 HTTP、空密碼或無驗證管理。
- 裝置憑證必須涵蓋實際使用的 IP／名稱，提供可信的首次部署及更新方式。不能把固定略過憑證警告作為正式流程。
- 首次部署安全韌體、憑證／密碼遺失與更換憑證的復原路徑需要文件化；不以重新開放 AP 作為復原手段。
- 首頁、狀態 API、診斷、trace、即時 log、`/normal`、OTA 都經過伺服器端驗證。不能只保護首頁。

### 3.2 寫入前授權與請求邊界

OTA 必須在 `Update.begin()`／第一次寫入前完成管理驗證、請求來源及 CSRF 檢查。CSRF 資訊應能在開始處理韌體內容前取得，例如自訂請求 header；不開放任意來源 CORS。

真正傳送映像檔的請求也必須獨立取得授權，不繼承上一個 HTTP 請求留下的全域授權旗標。授權不得因另一個用戶端的請求而錯置。

維持進行中事件不得 OTA 的規則，並以新鮮、有效的入口清空資料作為取得更新權的條件。更新交易具有獨立的獨占權與有界期限；一般維護倒數不能在合法寫入途中關閉網路。

中斷、逾時、映像不適用、寫入失敗或驗證失敗，均不得把不完整映像設成下次開機目標；必須清理更新旗標、鎖及網路活躍狀態。上傳失敗保留舊映像與新韌體開機後自動 rollback 是不同功能，後者不能在未配置並測試 bootloader／自檢前宣称具備。

### 3.3 活躍時間與濫用限制

網路封包在授權前仍會消耗接收、TLS 與驗證資源。可限制操作與持續活躍狀態，不能保證拒絕未授權請求零耗電。

未登入／驗證失敗的請求不能讀取資料、啟動 OTA 或延長高耗電維護狀態。重試限流、连接數、請求大小、讀寫及交易期限均需有界；不可用長時間 `delay()` 卡住偵測。也要避免簡單的全域永久鎖定讓攻擊者阻止合法管理。

登入不代表無限延長維護窗口。閒置期限與最長期限分開控制；背景頁面停止非必要輪詢，狀態輪詢不能無限制刷新最長期限。OTA 使用自己的交易期限。

## 4. 省電能力與排程

### 4.1 編譯及執行期能力

核對實際 Arduino core、ESP-IDF 版本、工具鏈、分割區及有效 sdkconfig，至少涵蓋：

- `CONFIG_PM_ENABLE`。
- `CONFIG_FREERTOS_USE_TICKLESS_IDLE`。
- 所用 HTTPS 元件及其 TLS 依賴。
- `esp_pm_configure()` 與 Wi-Fi 省電設定的執行結果。

不得在 sketch 裡補上同名 `#define`，冒充已啟用預編譯 SDK 沒有提供的功能。未支援的連線模式必須明確拒絕／回報；初始化失敗時回到可偵測的安全離線狀態，不能靜默退化成高耗電常駐模式卻回報省電成功。

ESP-IDF 自動 Light-sleep 使用其自身的 timer wakeup 協調。連線自動省電路徑不得沿用手動設定 timer wakeup 再強制 `esp_light_sleep_start()` 的做法。模式轉換時也須確認舊設定、計時器與 PM locks 不會殘留或互相衝突。

### 4.2 偵測优先與 PM locks

讓需要等待的工作真正等待事件或期限，不能只把手動睡眠條件移除，仍靠持續輪詢與極短 delay 宣称節電。

量距與 RFID 排程保持既有需求。RFID 收訊期間，需驗證 UART 時鐘、接收與 Light-sleep 的相容性；必要時使用範圍有限且成對釋放的 PM locks，而不是假設 Wi-Fi 能喚醒就代表 UART 也不會漏字節。

感測狀態機維持單一擁有者；網路工作不得直接競爭修改 `visit`。任何共享狀態、命令與紀錄快照都需要清楚的所有權和同步方式。HTTPS、下載及上傳不得藉由跨 task 全域旗標產生新的 OTA／事件競態。

連網／NTP／HTTP 等同步等待目前可能擋住主迴圈；這是本模式端到端驗收必須處理的相依項目，不能只驗證空閒時能睡。允許拆開 PR，但所有相依項未通過前，不能把連線待機標為可部署完成。

## 5. 斷線、重連與資源清理

STA 連線失敗或運行中斷線時，不開 AP、不進行每圈重試；使用有界嘗試與退避，維持離線偵測與紀錄能力。必須核對實際連線狀態，不能只相信保存的 `netMode`。

重連恢復後，先重新確認安全服務與省電能力再宣告模式恢復；不得重複建立服務 task、socket、佇列或 PM locks。Wi-Fi 關閉、服務停止與失敗清理須可以安全重複執行。

斷網重試與紀錄上傳的具體節奏，沿用或集中在 `app_config.h`，不在文件及多處程式複製一套數值。

## 6. 可觀測性

診斷至少要能區分：設定模式、實際模式、無法啟用原因、STA 狀態、管理服務狀態、管理／OTA 活躍狀態、有效建置能力與韌體識別。

自動 Light-sleep 不會自然增加舊有「包住手動 `esp_light_sleep_start()`」的統計。因此不能用舊 `sleep_calls` 為零，直接判定自動省電失敗；需要使用適合該 SDK 的 PM／睡眠觀測方法，並以整機電流作外部驗證。

取樣間隔觀測需涵蓋待機、事件、結案、上傳及管理請求，而不只有事件中的 `max_gap_ms`。報告平均值時也保留最大值／分布及受測狀態，避免平均值掩蓋短暫漏觀測。

此工作不要求修改 Google Sheets 既有紀錄欄位或 Apps Script 通訊格式。

## 8. 驗收矩陣

以下均為**待執行**，不是測試結果。

| 範圍 | 必測情境 | 驗收重點 |
|---|---|---|
| 建置 | 預設離線、可選連線、缺少 PM／TLS 能力的建置 | 可重現；不能偽造 sdkconfig 支援或無聲降級 |
| AP 禁用 | 開機時路由器關閉、SSID／密碼錯誤、運行中斷線、兩種 DEBUG 設定 | 不產生 AP；離線偵測仍運作 |
| 區網管理 | 連線待機閒置後由手機及電腦直接開網址 | 憑證驗證正常、要求登入；記錄首開與重開延遲 |
| 授權 | 不登入直接呼叫各端點、錯密碼、缺少／錯誤 CSRF、跨來源請求 | 無資料洩漏、無寫入、無未授權延長活躍狀態 |
| OTA | 事件中、入口狀態過期／無效、合法映像、錯誤映像、中斷／逾時 | 寫入前阻擋；正常成功；失敗不切換不完整映像並恢復狀態 |
| 偵測 | 實際貓咪經過、RFID 收訊，同時含 TLS 連線、狀態讀取、下載、上傳與重連 | 記錄全時段取樣間隔與 UART 結果；不能用空閒測試代表完整通過 |
| 期限 | 背景頁面、未授權輪詢、閒置及最長期限、OTA 跨越一般維護期限 | 能回到所選待機；無無限活躍或合法 OTA 被倒數打斷 |
| 清理 | 多次連線／斷線、模式及維護狀態切換 | 無 task／socket／heap／PM-lock 洩漏或殘留 |
| 功耗 | 同硬體、同供電與量測位置，比較離線與連線待機、一般事件及管理操作 | 回報實測平均電流與測量時段，不能只列晶片理論值 |
| 量測干擾 | 檢查 USB、除錯器、Serial 與 PM profiling 對省電的影響 | 記錄量測條件，避免以測試設備造成的差異誤判正式耗電 |

實機驗收報告需附實際 core／IDF 版本、有效編譯設定、韌體 commit、路由器／Wi-Fi 條件、供電與電流量測方法。URL 延遲、取樣間隔及電流結果需要可回查的證據；未有證據前不得修改正式預設。
